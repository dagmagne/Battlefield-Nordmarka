# Map data pipeline

`tools/geo/`: fetch scripts, `prep.py`, the lidar passes, `world.bin` blobs. Part of the developer notes indexed in `CLAUDE.md`; update this file when the system changes.

- **Map data pipeline (`tools/geo/`, Python, run by hand):** `fetch_dem.py` (public Terrarium terrain tiles, which use Kartverket's 10 m model for Norway), `fetch_osm.py` (Overpass; parking areas can also come from a separate `raw/osm_parking.json`), then `prep.py` writes `src/data/world.bin` and `raw/landmarks.json` / `raw/preview.png`. `geo.py` holds the origin and window size. `raw/` is git-ignored. Data credits: © Kartverket (CC BY 4.0), © OpenStreetMap contributors (ODbL).
- **Lidar passes (`tools/geo/`, run after `prep.py` with `tools/geo/.venv/bin/python`; the venv needs numpy, scipy, pillow, requests, rasterio, pyproj, made with `uv venv --python 3.12`):** `fetch_hoyde.py` downloads Kartverket's 1 m DTM (ground) and DOM (surface with roofs and crowns) for the window from the open WCS (`wcs.geonorge.no/skwms1/wcs.hoyde-dtm-nhm-25833`, coverage `nhm_dtm_topo_25833`, same with `dom`; CC BY 4.0), caches tiles in `raw/hoyde/` and resamples from UTM 33 to the local frame (`raw/dtm1.npy`, `raw/dom1.npy`; 4097², sample [j, i] at x = -2048 + i, z = -2048 + j). Each post-pass rewrites `world.bin` through `pack.py` (file lock, only its own blobs): `terrain.py` (blob `hgt` at 4 m and the insets listed in `INSETS`, currently the arena x -1064..160, z 792..1512 and Tryvann x -960..-360, z -1780..-1180), `buildings.py` (blob `bldh`, 3 bytes per building: eave 0.2 m, rise 0.1 m, flags 1 valid, 2 flat, 4 ridge along the short side, 8 a large outline with no roof in the lidar, which the game skips: stands and ski-jump parts; 84 % of the rectangles get a valid measurement, the rest keep the old guess; `--overlay` draws it), `canopy.py` (blobs `cov` and `canh`; buildings, the inruns and the TV tower are masked; run it after `buildings.py`; it removes the old `tree` blob). `compare.py` prints the error of the shipped grid against the DTM and writes hillshades to `shots/geo/` (the old 8 m grid was 3.1 m rms and up to 28 m off); `jumps.py topx topz endx endz` prints a ski jump's deck, width and wind-screen profile for the `LM` tables; `stands.py` (`profile`, `rake`, `image`) measures stands in any frame. `prep.py` itself needs `raw/osm.json` and `raw/dem.npy`, which exist only on the machine that first ran it: re-running it would renumber the buildings, so the passes work on the existing `world.bin`. A new area needs `geo.py` (origin, size), the fetch scripts, `prep.py`, then the passes.
