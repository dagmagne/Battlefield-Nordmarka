# Testing and measuring

Test hooks, every verification tool, known test noise and the performance baseline. Part of the developer notes indexed in `CLAUDE.md`.

## Test hooks
- **URL parameters:** `m=contact|convoy|tower|arena|cp|night` (a mission; implies the real world) `w=holmenkollen|frogner|fantasi np` (`np` skips the props mesh) `nohint nohud peace notrees trees=<level> hide=<letters> tfs=0 drs=0 tod=1..4 therm=1|2 q=<tier> perf debug auto mute veh=x,z,yaw cam=x,y,z,yaw,pitch lod=<mul> sx=<snow extents>`.
- **`window` globals:** `__ready __step(dt,n) __sim(dt,n) __pose __look __chase __aim(yaw,pitch,mode) __aimAt(x,y,z) __tod __tp(x,z,yaw,top) __info __waitFrames`, plus `__R __W __cam __veh __aimS __inp __api __ui __game __parts __audio` (`state count played live srcs nodes engine mg master start()`), `__infDemo(x, z, o)` (fills `G.inf` with soldiers around a point: `o.poses` list, `n`, `cols`, `sp` spacing, `yaw`, `aim`, `jit` yaw jitter, `move` (walkers and runners advance at their cycle speed), `dead` (seconds already dead); phases advance every frame), `__sol` (the soldier renderer: `out`, `nNear`, `nFar`, `reset()`), `__bld` (building records, boxes, states; `__game.bldHit(i, dmg, x, y, z, hot)` damages one) and `__collBench(n)` (time n `collide()` calls). `__step` switches to manual, deterministic stepping; `__sim` steps the logic (physics, combat, particles) without rendering, which is what makes scripted fights affordable. `__R.force=[throttle,steer]` scripts the driving, `__inp.fire` / `__inp.mg` the weapons (set `__ui.poll=()=>{}` first so the poll does not overwrite them), `__game.spawn(type)` adds an enemy, `__R.god` makes the player invulnerable, `__game.droneType(i)` / `__game.droneKey()` pick and launch a drone (`__game.drone` holds its state, `__game.dn` the stock).

## Tools
All tools drive a **headed** Chrome with the GPU enabled through playwright-core, at 1728×1117 and DPR 2 (MacBook Retina). They were written for the Mac and run on the Linux GTX 1060 machine; not tried on Windows. Shared options live in `tools/gpu.mjs`: `--port N` (or `GPORT`, default 8080), `--path P` (or `GPATH`, a checkout below the server root, e.g. `.claude/worktrees/<name>` when the server serves the main checkout), `--vulkan` (adds `--enable-unsafe-webgpu` and Vulkan for a Chrome without hardware WebGPU; not needed on Chrome 157 / Linux). **`GX11=1`** in front of any tool runs Chrome through XWayland with Vulkan: needed when the screen is idle or locked (the owner away), where the plain Wayland launch hangs or throttles `requestAnimationFrame` to 1 Hz; the adapter is still `nvidia pascal`. Frame-time numbers from `perf.mjs` are useless in that state (1000 ms frames); use `tools/vehgpu.mjs` or `treegpu.mjs`-style GPU timestamps with manual stepping. Every tool prints `[gpu] <adapter>` and warns on SwiftShader or llvmpipe; the container tools (`cshot`, `battle.sh`, `audio-test.mjs`) are what has been used since the tank conversion.
- `tools/vehshots.mjs outdir [--only leo,tigr,buggy,moto,train,t72,bmp,btr] [--near] [--aim] [--tod N] [--q query]`: every vehicle staged alone on the lake ice (and the parked trains, plus stations without one) from fixed views; the Leopard also driving, pivoting and reversing. `tools/vehgpu.mjs "q=high"` (with `TFILE=<other build>.html` for A/B): median GPU time on a Leopard close-up, a train and a group of eight enemies (2026-11-20, GTX 1060, drs=0, load 0.2–0.7, the build before the vehicle rebuild against the final one with the new BTR and T-72: high 37.4 → 40.1 / 33.5 → 34.2 / 40.7 → 42.8 ms, medium 10.1 → 11.8 / 9.9 → 10.2 / 12.8 → 13.6 ms). `node tools/leocheck.mjs` prints the Leopard's counts and proportions.
- `tools/shot.mjs`: single screenshot. `tools/multi.mjs`: a batch of shots in one session.
- `tools/poses.mjs` with `tools/scenes.mjs`: the 8 fixed verification scenes (real world). Render these after visual changes. The fantasy world has no scene set any more; check it by loading `?w=fantasi`.
- `tools/drive.mjs outdir [--video]`: scripted drive with consecutive frames (shimmer check), sparse frames and an optional mp4.
- `tools/cshot.mjs out.png "query" [--eval "js || js"]`: the same idea for containers without a GPU (headless Chromium, software WebGPU through SwiftShader, several seconds per frame at 960×620). One screenshot per `||`-separated snippet. Good for correctness, useless for performance.
- `tools/battle.sh outdir [tier]`: uses `cshot` to stage a fight on the open lake (models, gunner sight, a kill, the wreck, smoke screen, driving).
- `tools/audio-test.mjs [--port N]`: headless behaviour test of the sound (gesture start, engine, gun/reload, MG gate, enemy fire and kill, voice/node bound over 20 s of fighting, mute through M, the menu and a reload, `?mute`, no `AudioContext`, and the music under a gesture-required autoplay policy: start on picking a world, playing on in the game, U, the MUSIC button, M, the menu row and a reload). Nobody hears it; it checks the events and the graph.
- `tools/dronetest.mjs [outdir]` (GPU tools options): phase 1 behaviour test with `__sim` on the lake: nothing on the map until looked at, the sight spots, the contact goes stale, a muzzle flash spots, the bomber hits a stationary T-72's engine deck from 40 m and kills it with the second grenade, lands and is rearmed, the recon drone climbs to ~110 m and spots a BMP from 330 m, FPV still detonates. Saves map and drone-view shots.
- `tools/artytest.mjs [outdir]` (GPU tools options): phase 5A behaviour test on the lake: an Orlan watching ~15 s calls a barrage on the observed point (it stays there when the tank drives off), the ranging round lands 60–120 m off first and the rest within ~40 m, a tank that stays put is hurt and one that drives off after the ranging round is not, no barrage in peace mode or between waves, plus renders of a falling round, the impact and the craters (default `shots/phase5a/`).
- `tools/inftest.mjs [outdir]` (GPU tools options): phase 6 part B test of the infantry logic with `__sim`: an RPG team in a house engages at ~150 m and the rocket hits for 20–35, an HE round into the house kills or scatters it, the coax kills a standing soldier at 150 m and needs more rounds for a prone one, the tracks kill, a BMP stopping in contact dismounts a squad that advances by bounds and fires, an ATGM team on a height fires a guided missile, the minimap shows a soldier only once spotted, `G.inf.d` stays consistent, and the logic cost of 40 soldiers per tick (about 0.03 ms on the GTX 1060 machine). The soldiers themselves are drawn by part A. `tools/wavetest.mjs` also prints the infantry per wave and fails on a soldier inside a wall.
- `tools/supporttest.mjs [outdir]` (GPU tools options): phase 5 part B test of the own artillery: sight call lands within 30 m after 20–30 s, drone call lands where the camera looks, BMP and buggy killed and a T-72 damaged at the point, near-direct hits kill T-72s, one mission per wave and restock on a cleared wave, danger close hurts the tank, the B key and both ARTY buttons, no page errors. Renders in `shots/phase5b/`.
- `tools/roadtest.mjs [--runs N]` (GPU tools options): where the wheeled vehicles and BMPs drive (road, trail, off route, canopy), fails on a spawn in dense forest or much forest driving.
- `tools/lighttest.mjs [outdir]` (GPU tools options): phase 4 behaviour test: the four wheeled types drive with rolling wheels, a Tigr's Kornet steers onto the tank, smoke cuts its guidance (the missile is slowed in the test so smoke has time to form at lake range), the coax kills a buggy and a bike in a short burst but not a BTR, and the Motorised raid and ATGM ambush scenarios run (Tigrs fire). Note: on the test lake the tank's forward axis points away from the lake; tests aim along `L.ax/L.az` instead.
- `tools/airtest.mjs [outdir]` (GPU tools options): phase 3 behaviour test on the lake: the hatch MG shoots down a diving FPV (tracking with lead, like a player), an unopposed FPV does 25–40, an FPV searching nearby locks onto a still tank, smoke breaks a diving Lancet, the Orlan circles ~280 m out, feeds the enemy and is brought down, a cope cage cuts a bomber grenade to about a third. Saves the incoming arrow, the Orlan in view, the cage and close-ups of the Lancet and Orlan.
- `node --expose-gc tools/bridgecheck.mjs` (no GPU): the bridge queries on `meta.bridges`: `seg` against brute-force fine stepping on 4000 random rays (worst 0.5 cm), the STEP rule, `over`, `push` at both levels and its normals, a million mixed queries (about 0.15 µs each) without heap growth.
- `tools/bridgetest.mjs [outdir] [--shotsonly] [--noshots]` (GPU tools options): functional bridges with `__sim` on every built crossing (k 0 sites as below; the others: the under-route driven through, the over-route driven across at 8 and 15 m/s, a parapet on decks at least 11 m wide, the shell into the slab, blocked crossings: the barrier stops the tank; crossings outside the playable area are skipped). Milestone 2 adds: a BTR routed along Holmenkollveien drives through under both arena decks, a T-72 on trail 14 rides over the deck, a soldier walks across it and stays on it, an explosion on the deck leaves its chunks there, a mine on the road under the deck is not set off from the deck but is on the road. The k 0 tests on both arena sites: driving the road through under the deck, across the deck at 8 and 15 m/s (within 0.3 m of the top), into a parapet, a shell fired up into the slab, line of sight from above blocked and along the road open, the bomber's drop point on the deck, the sight ranging the deck from 300 m, a shot through the underpass hitting a T-72 beyond, an FPV under the deck and into the slab side, no drone launch under it, the commander camera under the slab; then renders (approach, under in both views, on top, side, site 2, night, thermal).
- `tools/minetest.mjs [outdir]` (GPU tools options; fixed in the bridges milestone 2: since the lidar terrain (e3b380f) the test lake is smaller, so the HE field is laid on the ice towards the lake centre and the gun gets time to traverse): phase 2 behaviour test on the lake: a buried field is hidden, driving into it blows a track (15–25 hull, immobilised under full throttle, TRACK pill, the crew marks the rest), it drives again after the repair, an HE round clears mines, a rocket strike scatters ~10 marked surface mines, an MG burst sets one off, a recon drone marks a buried field 250 m out, an enemy on a road skirts its own field and still closes in. Saves field, thermal, surface-mine, map and drone-view shots.
- `tools/wavetest.mjs [--query w=frogner] [--seed N] [--move] [--gpu --port N --path P]` (`--gpu` uses the installed Chrome on the real card; the default needs Playwright's own headless shell, which is not installed on the Linux machine): plays all waves headless with `__sim` and an invulnerable player; prints per wave the scenario, each vehicle's role, spawn bearing, distance track and route use, and fails on NaN, vehicles inside buildings or repeatedly stuck. Takes several minutes.
- Infantry (phase 6A): `tools/infshots.mjs outdir [--dist 5 --views front,side,q,q2,back --poses .. --therm 1 --tod 1]` (one soldier per pose, close-ups), `tools/infgroup.mjs outdir [lod]` (40 soldiers at 15–160 m, daylight, thermal, golden hour, night, the open lake for long ranges; `lod` = shots either side of the 120 m LOD switch), `tools/infperf.mjs` (GPU time with and without 40 soldiers, A/B), `tools/infdeath.mjs outdir` (four soldiers killed at once, frames 0–1.5 s), `tools/infwalk.mjs outdir` (walker and runner on the open lake, 12 frames), `node tools/soldiercheck.mjs` and `node tools/soldierpose.mjs` (no GPU).
- `tools/missiontest.mjs [outdir] [--noshots] [--only id]` (GPU tools options): game modes and missions with `__sim`: every mission starts and prints its placements (fails on a wheeled vehicle in dense forest or anything within 300 m of the tank), each is played by script (zones by teleport, tagged vehicles through `__game.kill`), and the ways to lose are provoked by leaving the enemy alone (the column drives the whole road, the counter-attack takes the tower, the first attack takes the arena, the clock); peace mode, back to the waves, restart; then the start screen on desktop and at 852×393 with touch (mode → mission → briefing → Roll out, the objective pill clear of the wave pill and the map) and renders in `shots/missions/`. About four minutes.
- `tools/nettest.mjs [outdir]` (GPU tools options): the camouflage net with `__sim` on the lake: not while driving, 8 s with the countdown pill, time to detection by a T-72 at 150 / 250 / 350 m with and without (at least three times longer, or never), an enemy that has detected the tank keeps it, what throws the net off, the drone leaves it up, restart, an Orlan over the open ice (watches a bare tank, never a netted one); the phone layout with the seventh button; renders in `shots/net/`.
- `tools/langtest.mjs [outdir]` (GPU tools options): the Norwegian UI in the browser on desktop and at 852×393 with touch (start screen, mission cards, help, briefing, HUD and objective pill, menu; no button or pill text wider than its element), message timing and queue, and the menu row switching to English with a reload; renders in `shots/lang/`.
- `node tools/langcheck.mjs [-v]` (no GPU, no browser): the Norwegian translation: every mission text, every plain message literal in `src/`, and about sixty sample messages through the patterns.
- `tools/haptest.mjs [--port N]` (like `audio-test.mjs` it launches Playwright's own headless shell, which is not installed on the Linux machine, so neither runs there): vibration behaviour test with a fake gamepad that records every `playEffect` (no pad, idle, driving, gun, hits, tree, near and far explosions, MG rattle, levels, off, disconnect). Uses `__sim`, so it runs where software WebGPU cannot render (in the cloud container `cshot` currently dies with 'A valid external Instance reference no longer exists' on `__step`, also on unchanged code).
- `tools/perf.mjs`: a 60 s drive that prints frame-time and GPU-timestamp stats (avg/p50/p99/max, hitches). The in-app overlay is the backquote key or `?debug`.
- `tools/lodcmp.sh`: forces each tree LOD on the same view and prints the mean colour per LOD, to catch LOD pops.
- `tools/treeviews.mjs outdir [query]`: tree look-check renders (forest close-up and mid range, tower forest, distant forest, golden hour, night, tops close-up). `tools/treegpu.mjs`: median GPU time on three tree-heavy static views; `TFILE=<other build>.html` (also honoured by `multi.mjs` and `perf.mjs`) measures another build from the same server, so A/B runs can alternate (ABBA: the GPU warms up and the first run is always faster). `multi.mjs` jobs take `steps` (manual stepping in chunks of 10) and `poses.mjs` steps in chunks, because hundreds of full-resolution frames queued in one `__step` lost the GPU device on the GTX 1060.

## Performance baseline
- **Tank-game baseline (2026-11-17, Linux, GTX 1060 6GB, driver 580, Chrome 157, adapter `nvidia pascal`; idle desktop, load ≈ 1.3):** `tools/perf.mjs` at 1728×1117 DPR 2 (3456×2234 backing), real world, Frognerseteren, tod=1. Frame times include the ~3 s load hitch in max/avg.

  | run | frame avg / p50 / p99 ms | GPU avg / p50 / p99 ms | DRS scale |
  |---|---|---|---|
  | `q=high` (DRS) | 24.5–28.2 / 16.7–33.3 / 33.5–49.9 | 22.7–26.1 / 22.9–26.5 / 28.6–33.4 | 0.6 |
  | `q=high&drs=0` | 40.9 / 33.4 / 66.7 | 38.2 / 39.2 / 42.5 | 1.0 |
  | `q=medium` | 18.1 / 16.7 / 16.9 | 10.8 / 10.6 / 13.2 | 0.8 |
  | `q=medium&drs=0` | 18.1 / 16.7 / 16.8 | 11.2 / 11.1 / 13.7 | 0.8 (tier) |

  Two high runs differed by about 15 %, so use `drs=0` for A/B comparisons. High does not hold 60 fps on this card at this resolution; medium does with headroom.

## Gotchas
- `tools/scenes.mjs` indexes into `trails[0]`; an index past the trail length gives NaN and a black frame that also poisons the following scenes.
- The mp4 height has to be even for ffmpeg (`-vf scale=1728:1116`).
- Unexplained and rare (about 2 of 18 test runs on the Linux machine, in `airtest` and `bridgetest`): a burst of a few hundred `[pageerror] undefined` during a run, i.e. something throws or rejects with no value once per frame for some seconds, after which the run's checks still pass. Re-runs are clean. No `throw` or bare `reject()` exists in `src/`; not reproduced on demand, cause unknown (several headed Chrome instances were running at the time).
- `tools/roadtest.mjs` is not stable from run to run on the same build: its last check (wheeled vehicles driving through forest off route, limit 5 %) gave 2.7 and 5.3 on the same commit within minutes (2026-11-19). Treat a single failure near the limit as noise and repeat it.
